## Troubleshooting

| Issue                                                                        | Likely cause                                                                                            | Fix                                                                                                                                                                                           |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| App always lands on onboarding, even after a successful login                | Secure storage token isn't persisting, or `GET /user/me` is failing on relaunch                         | Confirm the device/emulator supports secure storage; check that the access token from `TotpService.enable`/`verify` is actually passed into `AuthSession.setSession()`.                       |
| `Login failed (4xx/5xx): ...` exceptions surfaced as generic errors          | Backend returned a non-200 from `/auth/login`                                                           | Check the exception message (includes the raw response body) for the backend's reason; verify credentials and that the account has completed admin/worker setup.                              |
| "Unsupported user role." snackbar after login                                | Backend returned `recycling_center_worker` (or any role other than `company_admin`/`refinery_operator`) | Known gap — `RoleRouter` doesn't currently handle this role. See `architecture-layers.md`.                                                                                                    |
| Worker list / booking list appears empty for an admin                        | `WorkerService`/`BookingService` calls are unauthenticated or scoped to the wrong `companyId`/`userId`  | Confirm `AuthSession.currentUser` is populated before `MainLayout` constructs `WorkerService`/`BookingViewModel` — both read `accessToken`/`companyId` from the session at construction time. |
| Catalog tab shows the same static items regardless of backend state          | `CatalogRepository` currently serves a hardcoded, in-memory list, not live data                         | Expected with the current implementation — see `architecture-layers.md`.                                                                                                                      |
| TOTP setup screen shows an error immediately on entry                        | `TotpService.setup()` failed for the given `tempToken` (e.g. expired temp token)                        | Have the user log in again for a fresh temp token; temp tokens are short-lived.                                                                                                               |
| `flutter pub get` fails on `flutter_secure_storage` or platform build errors | Missing/mismatched platform toolchain (Android minSdk, iOS deployment target, CocoaPods)                | Run `flutter doctor` and resolve reported issues; ensure CocoaPods is up to date on macOS.                                                                                                    |
| Mobile works against the wrong backend environment                           | Base URL is hardcoded per-service, no env-var switch (see `security-measures.md`)                       | Manually edit the `baseUrl` constant in each service file until an environment-variable strategy is added.                                                                                    |
